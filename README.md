Тестовое задание Unity: "Система инвентаря и крафта"

Реализовано:
- Инвентарь с drag and drop.
- Разделение предметов - удерживайте shift при перетягивании предмета, чтобы разделить стак пополам.
- Крафтинг. Рецепты не зависят от позиции в сетке.
- UI с счётчиком предметов в стаке и иконками предметов.
- Кнопка "Заполнить случайными предметами"
- Кнопка "Очистить инвентарь"
- Тултип с информацией о предмете.

Архитектура:
Логика разделяется на несколько систем:

1) Предметы
Эта часть проекта отвечает за определение и создание предметов.

Item (предмет) - представляет собой определённый игровой предмет и его количество. Содержит в себе ItemDefiniton.
ItemDefinition - хранит в себе неизменяемые данные о предмете (ключ, размер стака, спрайт). ItemKey - своеобразный ID предмета, на основе которого происходит сравнение предметов. DisplayName - отображаемое, не обязательно уникальное имя предмета. В данной реализации принимает то же значение, что и у ItemKey.
IItemConfig - конфигурация, на основе которой собирается ItemDefinition предмета.
IItemConfigLoader - загружает конфиги предметов на основе ключей предмета. Текущая реализация интерфейса загружает и кеширует конфиги из ScriptableObject-ов, но интерфейс позволяет позже реализовать другой загрузчик - например, на основе .json файлов.
ItemDefinitionManager - создаёт ItemDefinition предметов на основе их конфигураций и кеширует их по ключам.
ItemFactory - создаёт новые предметы по ключу.

2) Инвентарь (InventorySystem)
Эта система отвечает за управление инвентарём.
Инвентарь содержит в себе слоты. Реализует методы для добавление и удаления предметов в разных количествах.
Работает по принципу MVP - InventoryPresenter отвечает на события из InventoryView, взаимодействует с логикой инвентаря, собирает и передаёт данные для отображения содержимого слотов.
ItemSlot - каждому слоту задаётся свой номер. Слот хранит в себе предмет. Предоставляет свойство IsOccupied. Слот можно сделать блокирующим с помощью параметра canAcceptItems - в этом случае в него нельзя будет положить предмет, только взять.
IItemSlotView - реализует события drag and drop
InventoryGenerator отвечает за случайное заполнение инвентаря и его очищение.

3) Крафт (CraftingSystem)
Эта система отвечает за ремесло.
CraftingGrid - содержит в себе слоты подобно инвентарю, но в расположении 3х3. Также отслеживает уникальный слот для результата крафта.
Работает по принципу MVP - CraftingGridPresenter отвечает на события из CraftingGridView.
Recipe - содержит информацию о рецепта крафта: ключ и количество создаваемого предмета, а также необходимое расположение предметов в виде двумерного массива с ключами предметов.
Crafter - CraftingGridPresenter обращается к нему при изменении предметов с сетке крафта. Crafter пытается распознать один из рецептов. При успехе, в слот с результатом помещается созданный предмет. Проверяет все возможные положения рецептов, если для этого есть пространство в сетке.

4) Функция Drag and Drop (DragAndDropSystem)
Так как drag and drop должен работать между инвентарём и панелью крафта, созданы интерфейсы ISlotContainer и IDragSlotContainerView. 
Инвентарь и сетка крафта реализуют интерфейс ISlotContainer. Этот интерфейс отвечает за взаимодействие со слотами для предметов. 
InventoryView и CraftingGridView реализуют IDragSlotContainerView, который предоставляет связанные с Drag and Drop события.
У контейнеров есть свой ключ. События drag and drop передают ключ контейнера и номер слота, с которым они связаны, чтобы система смогла правильно отреагировать на него.
За выбор правильного контейнера отвечает класс SlotContainerResolver.
Перетягиваемый предмет удаляется из инвентаря и хранится в ItemDragState. IDraggedItemView отображает изображение перетягиваемого предмета и следует за указателем пользователя.
DragAndDropPresenter связывает различные IDragSlotContainerView с IDraggedItemView и ItemDragState.

5) Тултипы (TooltipSystem)
Эта система реагирует на события HoverStarted и HoverEnded, вызываемые наследниками IItemHoverSource.
CraftingGridView и InventoryView реализуют этот интерфейс. События вызываются в ответ на OnPointerEnter и OnPointerExit, распознаваемые в ItemSlotView.
В ответ на события система обновляет и перемещает ITooltipView.

Подходы и инструменты:
- Result<T> - utility структура, которая более явно даёт понять разработчику, что результат операции может быть null.
- Для подгружаемых в рантайме ассетов используется SimpleAssetLoader, работающий на основе Addressables. В данном проекте с помощью него загружаются только конфигурации предметов, рецептов и инвентаря.
- Для инициализации сцены используется VContainer. Настройка происходит в InventoryLifetimeScope. Это позволяет зарегистрировать классы по их интерфейсу, что, к примеру, полезно для системы Drag and Drop, получающей список всех зарегистрированных ISlotContainer и IDragSlotContainerView.
- Для распознания удерживания shift используется простое событие из InputSystem.
